## 2. Назначение

Автоматический мониторинг одного или нескольких Telegram-каналов (публичных и приватных, в которые вступил user-аккаунт) и мгновенное оповещение пользователя при появлении сообщений, содержащих заданные ключевые слова.

### Ключевые ограничения Telegram

| Способ | Возможности | Ограничения |
|--------|-------------|-------------|
| Bot API | Получение `channel_post` | Бот должен быть **администратором** канала |
| Userbot (Telethon / MTProto) | Любые каналы, куда вступил аккаунт | Требуется номер, api_id/api_hash, сессия. Риск FloodWait |
| Парсинг t.me/s/ | Публичные каналы | Только публичные, задержка, нестабильность |

**Выбранный подход:** гибрид — мониторинг через user-сессию (Telethon), уведомления и управление через Bot API.

## 3. Анализ конкурентов (ключевые выводы)

### Сравнение репозиториев

| Критерий | crazypeace/tg-keyword-monitor-bot | Riniba/TelegramMonitor | afolivieri/streaming_overseer |
|----------|-----------------------------------|------------------------|-------------------------------|
| Стек | Python + Telethon | C# + Web UI | Python + Telethon |
| Управление | Команды бота + YAML | Web UI | Текстовые файлы |
| Matching | Простой OR + case-insensitive | Exact / Contains / Regex / Fuzzy + Exclude + Priority | Substring + модификаторы |
| Хранение | YAML + session | SQLite + архив | Файлы |
| Полезность | Базовая схема | Система правил | Простота |

**Что берём за основу:**
- Схему «user-сессия мониторит → бот уведомляет» (crazypeace и большинство проектов)
- Типы matching и Exclude/Priority (идеи из Riniba)
- Обработку FloodWait, session-файл, last_message_id
- Простоту на старте (файлы → потом SQLite)

## 4. Функциональные требования

### 4.1. Управление ключевыми словами
- Добавление / удаление / список
- Регистронезависимый поиск
- Поддержка:
  - Contains (по умолчанию)
  - Exact
  - Regex (поздний этап)
  - Exclude-слова (минус-слова)
- Хранение в SQLite

### 4.2. Управление каналами
- Добавление по @username или ссылке
- Удаление и список
- Проверка доступности (аккаунт должен состоять в канале)

### 4.3. Мониторинг
- Постоянный мониторинг новых сообщений
- Проверка текста, подписей к медиа, превью ссылок
- Антидубли (по message_id + channel)
- Пауза / возобновление

### 4.4. Уведомления
- Отправка в личный чат с ботом
- Содержание: канал, фрагмент текста с подсветкой, ссылка на оригинал, совпавшие слова
- Защита от спама уведомлений

### 4.5. Дополнительно (после MVP)
- История срабатываний
- Статистика
- Фильтр по отправителю
- Дайджесты

### 4.6. Команды бота (MVP)

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие + краткая инструкция |
| `/help` | Список команд |
| `/add_keyword <слово>` | Добавить ключевое слово |
| `/del_keyword <слово>` | Удалить |
| `/keywords` | Список |
| `/add_channel @channel` | Добавить канал |
| `/del_channel @channel` | Удалить |
| `/channels` | Список |
| `/status` | Статус мониторинга |
| `/pause` / `/resume` | Пауза / возобновление |
| `/history` | Последние срабатывания |

## 5. Модули системы

1. **Config & Session Manager** — загрузка `.env` / config, управление Telethon-сессией
2. **Monitor Engine** — Telethon-клиент, `events.NewMessage`, FloodWait, reconnect
3. **Keyword Rules Engine** — matching (Contains / Exact / Regex / Exclude)
4. **Channel Manager** — CRUD каналов
5. **Notification Service** — отправка через aiogram
6. **Bot Command Handler** — обработка команд
7. **Storage Layer** — SQLite (ключевые слова, каналы, история, last_ids)
8. **Logger & Status** — логирование и `/status`

## 8. План разработки по спринтам

### Спринт 0 (1–2 дня) — Подготовка
- Структура проекта, `.env`, requirements
- Логин Telethon + сохранение сессии
- Простейший aiogram-бот с `/start`

### Спринт 1 — MVP Core (3–5 дней)
- Monitor Engine
- Простой Contains-matching
- Жёстко заданные каналы и ключевые слова
- Уведомления в личку
→ **Результат:** уже ловит и уведомляет

### Спринт 2 — Управление (3–4 дня)
- Команды управления ключевыми словами и каналами
- Хранение в SQLite
- Пауза/возобновление
→ **Результат:** полноценный управляемый MVP

### Спринт 3 — Устойчивость (2–3 дня)
- FloodWait + reconnect
- Антидубли
- История + `/history` + `/status`
- Exclude-слова

### Спринт 4+ — Улучшения
- Regex, Exact
- Docker
- Подготовка к переносу на Java

**MVP считается достигнутым в конце Спринта 2.**

## 10. Критерии приёмки MVP

1. Бот принимает команды управления ключевыми словами и каналами
2. При появлении сообщения с ключевым словом пользователь получает уведомление ≤ 60 сек
3. Система переживает перезапуск (сессия сохраняется)
4. Есть базовая обработка FloodWait
5. Документация по запуску присутствует
